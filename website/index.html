The cost of raw context

Every turn re-sends the bloat

Native Read/Grep loads whole files into the model. Long chat history compounds. Token Reducer runs before reasoning — indexing, routing, retrieval, and compression with budgets you control.

◎

Context bloat

Indexed corpora can reach tens of thousands of tokens. Sending the pool raw burns budget on noise.

$

Compounding cost

Published benchmark: about $34.30 saved per 100 queries versus shipping full context (v1.4.0, same codebase corpus).

?

Black-box retrieval

Without a spine, “why this chunk?” is guesswork. Token Reducer separates policy, signals, and outcome — replayable by trace_id.

How it works

Three layers: classify → route → compress

Hooks on UserPromptSubmit, orchestrated stages, and a control plane that emits sibling artifacts under one trace.

Simple

  • ~0.52× retrieval scale
  • Subagents & LSP skipped
  • Light compression under token threshold

Tool

  • One skill from registry
  • ~0.72× retrieval, LSP on
  • Reducer only above ~2800 token mass

Complex

  • Full subagent chain
  • Neighborhood expansion when allowed
  • Heavy compression + expansion path

Built for trust

More than shrinking text

Hybrid explainability

One deterministic context_optimization_line in model context (~15 tokens). A 3–6 line sidecar for humans. Full spine JSON only in verbose mode — no LLM “explanation” on the hot path.

Trace bundle

Same trace_id links audit spine, signal snapshot, gate decision, and decision_trace_v2 — policy vs signals vs outcome stay separable.

Subagents & routing

Execution tiers (simple / tool / complex) cap cost before retrieval expands. Subagent chain runs only on complex paths; tool tier picks one atomic skill.

Disagreement handling

FTS vs vector overlap stored once in the spine; flags like disagreement_present flow to confidence bands and the public trace — deterministic, replayable.
